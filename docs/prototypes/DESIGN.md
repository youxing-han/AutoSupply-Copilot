## 参考的现有产品与取舍

- MRPeasy 的缺货清单：先集中处理需要关注的物料，再进入物料详情与采购需求。
  官方依据：https://www.mrpeasy.com/resources/user-manual/stock/critical-on-hand/
- MRPeasy 的物料详情：将物料编码、供应商采购条件与库存预警等依据关联到具体物料。
  官方依据：https://www.mrpeasy.com/resources/user-manual/stock/items/details/
- Inventory Planner 的补货页：从多物料清单进入单项详情，同时考虑现有库存、订单和预计到货日期。
  官方依据：https://help.inventory-planner.com/en/articles/589017-replenishment

参考的是官方公开说明中的功能组织，没有登录付费后台，也没有声称逐像素复刻商业产品。
Inventory Planner 主要面向零售补货，其需求预测、收入损失等功能不直接移植为汽车生产结论。
外观采用浅色、深绿主操作、克制的字体层级，减少装饰、空白和重复卡片。

## 页面结构与交互

1. 风险总览：三项业务指标，左侧物料清单和小型趋势，右侧单物料曲线、缺口说明与采购到货。
2. 数据准备：物料与库存、逐日需求、采购到货、供应商分开显示；只显示所选物料的逐日需求。
3. 场景比较：当前计划与按原计划到货比较，展示真实模拟缺口和曲线差异。
4. 智能解读：展示确定性计算解释与拟接入状态，不伪装模型在线或虚构问答成功。

上方选择先加载再运行；编辑草稿和最后分析快照独立。更改库存、需求、到货时间、订单数量或状态后标记结果过期。
原型以相对天数编辑到货（第1天为2026-10-14），正式接入时保留日历日期输入和完整日期校验。
原型没有接入 Excel 上传/下载、应急方案执行、PDF 和真实 Ollama 问答。Excel 按钮明确禁用，现有应用功能仍保留。

## 中文范围

仅保留品牌、物料编码和 Excel 等必要名称。订单状态、风险名称、表头、操作按钮和解释使用中文。
正式接入时内部仍可保留 `CONFIRMED` 等稳定枚举值，展示层映射为“已确认”等中文，不能通过改枚举破坏计算。
例如 `opening_available` 为“期初可用库存”，`confirmed_receipts` 为“已确认到货”，`unmet_demand` 为“未满足需求”，
`projected_balance` 为“当日供需余额”，`closing_available` 为“期末可用库存”。
截图中的排序、隐藏列、上传等英文也属于验收范围；需检查组件是否支持稳定的中文配置，必要时改用中文交互，不以不稳定的 CSS 文字覆盖宣称完整翻译。

## 新增模拟参考数据（尚未接入生产应用）

- 多物料数据包：12种汽车零部件，包含传感器、轴承、控制器、制动模块、电池连接组件、线束、水泵、阀、散热器、连接器、密封圈和摄像头。
- 六类情景：平稳排产、供应商延期、排产高峰、订单待确认、周末检修、集中到货。
- 14/30/60天查看周期；不同周期使用同一条60天业务时间线的前缀，不因查看周期改变原有订单数量。
- 日需求由明确的星期排产系数与周排产系数生成；正常情景周日为0、周六减产；检修情景周六也为0。
- 排产高峰只提高第7—10天需求；延期只移动部分首笔订单四天；待确认只改变部分首笔订单状态；集中到货将收货集中到每七天的周期末。
- 同一数据包的场景保持期初库存和订单数量一致。曲线起伏来自分批到货和有依据的模拟需求，不使用随机抖动或手绘结果。
- 单物料核验包：库存800、日需求80、第8天到货500；延期为第12天。正常14天无缺口且期末180，延期14天缺口80且期末260；正常30天缺口1100。
- 名称、供应商、采购安排和排产系数均完全虚构；只是可解释的业务假设，不代表真实企业参数或行业实测统计。

业务规则复用 `agent/inventory_planning.py`：当天先收货再消耗；未满足需求单独记录、不结转；待确认订单不计入。
生成器从真实 Python 模块计算所有初始曲线；浏览器编辑后的逐日重算与该模块输出交叉验证。
