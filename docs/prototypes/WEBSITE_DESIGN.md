# 三模式整站界面讨论稿

本轮按用户澄清，将原型范围扩展到全部三种分析模式，同时增加绿色背景，形成统一的网站布局。
阶段仍是先讨论原型，再实际接入；没有替换正式 Streamlit 应用，也没有修改业务算法、启动脚本或模型配置。

## 结构

- 全站：深绿页眉、浅绿背景、淡绿导航与标题区域、白色数据面板、深绿主要操作。
- 顶部始终显示三个模式入口，不把动态模式内部导航误认为整个应用的模式。
- 单物料分析：左侧业务参数，右侧风险判断、库存覆盖/采购等待图、潜在缺口与参考补货。
- 多物料批量分析：参考情景、显式加载/运行、风险排序清单、库存/需求编辑、选中物料详情。
- 动态物料计划：保留原型的风险总览、数据准备、场景比较和智能解读，统一到全站样式。
- 批量清单可以进入单物料详析，也可查看同编码的动态物料。

静态参数与动态数据独立。点击“查看动态计划”只定位到动态参考数据中的同编码物料，
不会将静态日均需求偷偷变成逐日生产计划，也不会自动复制或覆盖另一模式的库存、需求和采购订单。

## 数字与功能边界

单物料和批量参考数据来自四组、每组12种虚构物料。
使用既有 `calculate_inventory_metrics` 和 `evaluate_supplier_risk` 生成核验结果，
浏览器重算与现有公式对照。没有为了配色或展示预先指定风险等级。
动态模式继续使用原有12物料/6情景/14、30、60天原型。

当前可演示切换模式、修改参数并重算、批量编辑、从清单进入详析、动态曲线与对照。
上传 Excel/CSV、PDF、真实 Ollama 问答仍明确标记接入时启用，没有把讨论稿当作已完成生产接入。
原有应用中的真实功能保持原样；用户反馈的真实 AI 故障仍待实际实施时重现并修复。

## 运行与验证

```powershell
.\.venv\Scripts\python.exe docs/prototypes/build_website_preview.py --output '<授权目录>\autosupply-website-redesign.html'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`verify_website_preview.cjs` 参数为生成片段和截图目录；复用原型文档中的 Playwright 与浏览器环境变量。

2026-10-14 验证：

- 完整回归135项通过，0失败；`.runtime/website-preview-tests.log`。
- 48组静态参考结果与既有 Python 模块一致。
- 原动态原型234组逐日结果交叉核对继续通过。
- 单物料重算、零需求、中文负数校验、旧结果提示、批量编辑、从批量到单项/动态、切换模式后保留动态物料均通过。
- 三个模式在1440×900、1280×720、1024×900、390×844、320×780均无页面横向溢出；宽表仅在自身区域横向滚动。
- 检查了单物料1440、多物料1440、动态1280截图；没有浏览器脚本错误。
- 低高度窗口中的曲线按实际绘图区高度生成坐标，避免压缩整幅图导致文字变小。
- 没有调用真实模型，没有 Git Push。用户已有三个脚本/测试修改不纳入本次提交。

本轮讨论重点：三个模式的整体排版、绿色背景的用量、信息密度与导航层级。
